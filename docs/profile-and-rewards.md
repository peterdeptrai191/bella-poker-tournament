# Display names and tournament rewards

Accounts now have a separate `displayName` (2–22 normalized characters). Username/password, account ID, coins, owned skins and admin permissions remain attached to the original login identity. Existing accounts fall back to the first 22 characters of their username. The account toolbar opens a name editor, and the create/join name fields can also save a new display name. Names are escaped in the client; control and bidirectional override characters are rejected. Room seats refresh names from the authenticated account record. The existing global display-name reservation prevents choosing another account’s login/display name; account IDs and room tokens still identify each person. The renameAccount API and setDisplayName alias share the same validation and reservation.

All-human tournaments pay the champion **1 coin per entrant**, i.e. 2→2, 3→3, …, 9→9. Any room containing a bot keeps the prior 1-coin reward if a human wins; bot winners receive no account credit. The server freezes entrant count and reward policy when the tournament starts. Eliminations and client-supplied amounts do not change the payout. Each account receipt records the actual credited amount, preventing duplicate credit after concurrent requests, retries or refreshes. Already rewarded rooms are not retroactively paid again. Existing started rooms without a snapshot derive their policy from the frozen roster; never-started rooms do not pay.
